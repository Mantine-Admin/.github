# Security Policy

**Do not report security vulnerabilities through public issues, discussions or pull requests.**

## Reporting a vulnerability

Use GitHub's private vulnerability reporting: open the **Security** tab of the affected
repository and click **Report a vulnerability**
(for the framework: <https://github.com/Mantine-Admin/mantine-admin/security/advisories/new>).

Please include:

- the affected package(s) and version(s);
- a description of the issue and its impact;
- steps or a proof of concept to reproduce it.

## What to expect

- We acknowledge reports within 5 business days.
- We keep you informed while we work on a fix and agree on a disclosure date with you.
- We credit reporters in the advisory, unless you prefer to stay anonymous.

This is a volunteer-run project, so these are best-effort targets.

## Supported versions

| Version            | Supported          |
| ------------------ | ------------------ |
| Latest release     | :white_check_mark: |
| Older releases     | :x:                |

Before `1.0`, only the latest minor release receives security fixes.

## How we handle security fixes

Security reports and fixes are handled by human maintainers only, in a private fork
attached to the security advisory. AI agents never receive undisclosed vulnerability details.
